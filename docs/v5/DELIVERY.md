## 从明信片到全站的转译

源图使用用户提供的 `桃花.ai`，通过其 PDF 兼容图层读取原始矢量曲线。保留桃叶锯齿、五瓣花、米白外边和暖卡其细描边；没有把整张方案图当作信封贴图。源文件只读使用。

| 视觉元素 | 全站应用 |
|---|---|
| 叶绿、桃花粉、奶油底色 | 首页纸张、活动来信、三校卡签、信纸、主次按钮、收藏套 |
| 花叶组合的异形轮廓 | 首页封签、信封角饰、活动信封角标、明信片正反面、完成页印花 |
| 米白厚边 + 暖卡其外轮廓 | 明信片裁切边，信封、纸面和按钮使用相应的双线/薄边语言 |
| 温和自然的纸品感 | 保留轻微纸纹和接触阴影，主要依靠实色、明度和前后遮挡建立层次 |
| 中文书写气质 | 本地化 Noto Serif SC 标题字体，正文和控制区使用清楚的无衬线字体；移除装饰性英文刊头 |

主要网页变量位于 `src/v5/experience.css`：文字 `#485b40`、重点绿 `#7c9067`、桃花粉 `#dc8d91`、纸张 `#faf5e8`、描边 `#b5b99d`、背景 `#efeee1`。SVG 内保留三组从源稿提取的粉绿配色，统一使用 A 款的轮廓作为当前系列组件。

字体文件在 `public/v5/fonts/`，附 OFL 授权文本。标题字库已按当前内容做子集，137,492 bytes；新增正式文案时应补充字库或换成完整、合规的本地字体。

## 空间与交互实现

舞台使用 1440×810 逻辑尺寸，等比适配两种目标屏幕。大信封的背板、内衬、盖、活动来信和前口袋属于同一父物体；开信期间始终保留同一个信封 DOM 实例。

1. 首页先提供静态 HTML 信封首帧，React 接管时沿用相同几何。脚本尚未就绪时的首次点击也会被接续处理。
2. 进入后连续三次阵风，随后间歇重复。叶片不同步移动，封签翘角与风的经过、阴影变化共用时间轴。
3. 封签揭开、盖翻起，信封移动 385 逻辑像素到屏幕下沿；前口袋留在画面中，裁切来自舞台边界。
4. 三张小信封依次从口袋后方抽出，再展开为扇形；六个活动分两组展示，三校筛选会先收回再抽出。
5. 鼠标聚焦时选卡抬起、邻卡退让；触摸采用第一次选中、第二次打开。选中来信抽离后，在对应位置展开成信纸；返回逆向执行。
6. 同一张花叶明信片从信纸后方抽出，支持双面 3D 翻转。确认时进入实色收藏套，再盖章，最后出现完成文案和唯一主操作。
7. 重置先收回物体，再让主信封回升、合盖、恢复封签。完成页没有沿用旧版的全屏透明面板。

React 状态与即时引用共同防止重复触发；筛选请求合并到最后一次。每个交互只保留当前时间轴、阵风、延时和聚焦 tween 引用，替换前先终止旧实例，卸载时统一清理。事件动画不累积注册到挂载期 GSAP context 中。页面失焦时暂停动画，恢复可见后续播。

reduced-motion 路径保留相同对象和操作顺序，缩短运动，关闭待机风。键盘焦点在动画完成且 React 更新 inert/disabled 后恢复。90 秒无操作提示、15 秒倒计时和异常数据恢复继续保留。

## 本轮发现并修复

| 问题 | 根因与修复 | 对应证据 |
|---|---|---|
| 开封中途巨大三角形与口袋分离 | 封盖背面在局部坐标内被倒置，翻转后铰链边错误；修正背面 SVG 的 Y 方向，保持基边与信封上沿相连 | `frames/open-050.png`、`open-contact.jpg` |
| 小来信像独立浮层 | 改为信封父物体内部的子层，置于内衬与前口袋之间；初始位置完全藏入纸袋 | `frames/open-075.png`、连续开封录屏 |
| 扇形侧卡信息被盖住、聚焦卡顶到筛选器 | 调整学校/日期/标题纵向位置，限制抬起幅度，重新分配标题和筛选区高度 | 两种尺寸的 `02-discover`、`03-focus` |
| 触摸第一次点击直接打开 | 浏览器合成的鼠标 hover/focus 抢先改变选择；短暂抑制紧随触摸的鼠标事件 | V5 触摸用例 |
| 动画完成后键盘焦点没有落到目标 | 焦点调用早于 React 解除 inert/disabled；延至下一帧恢复 | 键盘完整路径用例 |
| 明信片浅底白字不清楚、背面叶脉干扰阅读 | 正面标题换深色，背面提供独立奶油纸面和水平书写区 | `05-postcard`、`06-back` |
| 翻面花瓣尖端靠近标题 | 3D 透视会放大边缘外扩；给旋转中的外轮廓预留空间，重新设定明信片尺寸与位置 | `frames/flip-050.png` |
| 收藏时叶片露出收藏套下方 | 对齐卡片最终位置与收藏套裁切边；以实色前后纸面建立遮挡 | `07-complete`、`collect-contact.jpg` |
| 快速翻面后立即确认、连续筛选互相争夺动画 | 中断旧时间轴，从当前变换接续；筛选排队仅保留末次请求 | 收藏中断与快速操作用例 |
| 完成动画对象在 React context 内长期积累 | 用显式引用管理事件动画和清理，避免无限向挂载上下文追加 tween | `runtime-cycles.json` |

独立 Oil UI 静态复核曾指出侧卡遮挡、筛选间距、明信片文字对比等问题，以上已逐项修正。该复核并未对当前最终版本给出审美通过结论；最终视觉仍需用户实际体验评判。

未录屏的本机 Edge 开封采样：659 个帧间隔，median 8.3 ms、p95 8.7 ms、max 9.9 ms，超过 34 ms 的样本为 0，5.5 秒期间布局计算 4 次。它说明本机浏览器调度情况，**不能代替现场数字屏 GPU 性能、真实触摸硬件或人的流畅度评价**。录屏自身为 25 fps，不将其误报为 120 fps 视频。

浏览器复核与关键帧中未发现黑块、完成页错误遮罩或主要控件重叠；有限采样不能保证所有设备、所有输入时序均没有视觉问题。旧 V4 路径仍会输出其已有的缺失选择器 GSAP 警告。生产构建的 500 kB 提示来自保留的邮局实验懒加载模块（588.89 kB），未隐藏该提示。

## Skills 与参考的具体用途

| 能力 | 实际用途 |
|---|---|
| Oil UI | 从用户图确定既有方向，检查构图、阅读优先级；做独立静态复核并据图修正 |
| GSAP core / timeline | 以标签位置和重叠时序连接揭封、开盖、下沉、抽卡；逆向返回和中断衔接 |
| GSAP React / performance | 生命周期清理、显式动画归属、变换属性、暂停续播和重复会话检查 |
| animate / review-animations（Emil 的动画原则） | 限制无目的弹跳；按纸张动作安排缓动、遮挡、停稳与邻卡退让 |
| Frontend Skill / Taste Skill | 清除无意义小英文、胶囊堆叠和通用卡片墙，围绕信封这一具体物体构图 |
| Vibe-Upgrader | 沿已确认的产品方向做全站视觉介入；将功能通过与视觉质量分开记录 |
| 浏览器测试 / performance-optimization | 两分辨率实际 Edge 流程、键盘和触摸模拟、原始视频、帧级采样和生产包检查 |
| Skill governance | 检查外部来源和权限范围；复用已安装能力，不覆盖本地自定义 Skill，也未新增生产依赖 |
| MotionSites | 查看账户允许的 Halden Stories 参考，借鉴固定舞台和共享物体的连续叙事机制；没有复制其品牌或版式 |
| ReactBits | 阅读官方 Folder 组件的前后纸层机制作为结构参考；最终实现定制，没有引入该组件依赖 |

参考来源：[GSAP React](https://gsap.com/resources/React/)、[GSAP 官方 Skills](https://github.com/greensock/gsap-skills)、[Emil Skills](https://github.com/emilkowalski/skills)、[ReactBits Folder](https://github.com/DavidHDev/react-bits/blob/main/src/content/Components/Folder/Folder.jsx)、[MotionSites](https://motionsites.ai/)。

## 素材替换与复现

- `src/data.ts` 继续管理三校、活动与明信片的双向 ID 对应。
- `public/v5/botanical-a.svg`、`b.svg`、`c.svg` 和 `botanical-back.svg` 是可直接替换的外部素材。
- `src/v5/art.tsx` 的 `PostcardVisual` 只负责正反面内容，动画作用于外部物体容器。更换正式素材不必重写时间轴；若改变长宽比，需同步调整容器、旋转安全空间和收藏终点。
- `scripts/extract-botanical.py [AI路径]` 可从本次源文件重新提取，需要开发环境 PyMuPDF。其路径索引对应当前 AI 文档，重排源文件后需更新索引。
- `node scripts/capture-v5.mjs all` 重采浏览器证据；`node scripts/verify-v5-runtime.mjs` 重复会话检查。
- `python scripts/build-v5-evidence.py` 从真实截图/录屏制作验收联系表并完整解码，需 Pillow 和 imageio-ffmpeg。
- `node scripts/verify-v5-production.mjs` 在 5176 生产预览上检查无脚本首帧、提前点击和两尺寸完整流程。
